一、统一响应体 Result<T>

1.1 结构定义

{
  "code": 0,            // 0=成功；非 0 见错误码段
  "message": "success", // 提示信息；失败时为可展示的业务提示
  "data": { },          // 业务数据，可为 null
  "timestamp": 1725300000000
}
  • 所有 Controller 返回 Result<T>，禁止直接返回裸实体/裸 Map。
  • 分页场景 data 使用 PageResult<T>（见第三节）。
  • 成功代码 Result.ok(data)；失败抛异常，由全局处理器收口（禁止手工拼错误 Result）。

1.2 错误码段规划（4 位，分段按业务域）

码段域示例
0成功—
A0xxx通用/系统（参数、鉴权、限流）A0400 参数错误、A0401 未登录、A0403 越权、A0404 资源不存在、A0409 幂等冲突、A0500 系统异常
C0xxx基础 CRM（客户/线索/商机/跟进）C0101 客户不存在、C0102 客户名重复、C0201 线索已占用
B0xxx交易业务（标的/订单/汇款）B0101 标的已下架、B0201 订单状态不允许该操作、B0202 金额超单笔限额、B0301 汇款核销超核、B0302 重复到账确认
S0xxx系统管理（组织/角色/字典）S0101 角色不存在、S0102 权限点冲突
D0xxx报表/统计D0101 导出任务不存在
HTTP 状态码仅用于传输层语义（401/403/500 等），业务语义统一走 code 字段；前端按 code!==0 判定失败。

二、统一异常体系

2.1 异常类与处理映射

异常触发场景HTTPcodemessage 来源
BizException(ResultCode, detail...)业务规则校验失败（预期内）200异常携带ResultCode 描述 + 可选 detail
MethodArgumentNotValidException@Valid 参数校验失败200A0400首个字段错误消息
AccessDeniedExceptionSpring Security 越权403A0403"无权限执行该操作"
AuthenticationException未登录/令牌失效401A0401"未登录或登录已过期"
OptimisticLockerWrapperException（MP 乐观锁失败）订单/汇款并发修改200A0409"数据已被他人修改，请刷新后重试"
DuplicateKeyException唯一索引冲突200A0409"数据重复"
Exception未预期异常500A0500"系统繁忙，请稍后重试"（原始堆栈仅入日志，禁止外泄）

2.2 处理原则

  • 全局唯一收口：@RestControllerAdvice 的 GlobalExceptionHandler；业务代码只抛 BizException，不自行 try-catch 拼响应。
  • 所有异常写 ERROR/WARN 日志（含 traceId）；预期内业务异常 WARN，未预期 ERROR。
  • 需求依据：§5 安全「越权访问拦截」、数据一致性「幂等」、可维护「统一日志与错误追踪」。

三、统一分页规范

项约定
请求参数pageNum（默认 1）、pageSize（默认 20，上限 200，防大结果集拖垮库，对应 §5 性能）+ 各列表自有筛选参数
响应结构PageResult<T>：list / total / pageNum / pageSize / pages
实现MyBatis-Plus PaginationInnerInterceptor(DbType.POSTGRE_SQL)；Mapper 方法入参 Page<T>
排序默认 created_at DESC；排序字段必须白名单校验（防 SQL 注入）
深分页禁止前端无限制翻页；导出类需求走异步任务（ST-3），不走大分页

四、审计与公共字段基座

4.1 BaseEntity 公共字段（全实体继承）

字段类型填充方式
idBIGINT雪花算法（ASSIGN_ID）
created_at / updated_atTIMESTAMPMetaObjectHandler 自动填充（INSERT / INSERT+UPDATE）
created_by / updated_byBIGINT自动填充：取 SecurityContext 当前用户 id，未登录填 0（系统）
deletedSMALLINT@TableLogic 软删除；MyBatis-Plus 全局 logic-delete-field: deleted，默认 0/1

4.2 金额与自定义字段强约束（需求 §5/§6）

  • 金额字段一律 NUMERIC(18,4) + Java BigDecimal，全项目禁用 float/double 表达金额；手续费/总额只允许服务端计算（OD-1）。
  • 自定义字段统一 JSONB 扩展列（custom_fields），MyBatis-Plus TypeHandler 映射（CUS-DV-01 落地）。

4.3 操作审计日志（预留 SYS-DV-04 实现）

  • 注解 @AuditLog(action, targetType) 标注写操作方法；AOP 拦截写 audit_log 表（操作人、动作、对象、时间、IP、详情）。
  • 审计失败不阻断业务（try-catch 吞掉，仅记日志），符合"日志旁路"原则。
  • 本设计仅定接口形状；拦截器实现归 SYS-DV-04 任务。

五、缓存与对象存储抽象（方案A本地开发适配）

5.1 双接口设计

接口方法（最小集）dev 实现（@Profile("dev")）prod 实现（@Profile("prod")）
CacheServiceget / put(ttl) / evictCaffeine（进程内，yml spec 最大 1 万条 / 30m）Redis（含 Spring Cache type=redis）
ObjectStorageServiceupload / download / delete / presignedGet本地磁盘（app.storage.local.base-dir，路径含日期分桶）MinIO S3 SDK（bucket: crm-attachments / crm-contracts）

5.2 切换规则

  • 业务代码只依赖接口，禁止直接 import Caffeine/Redis/MinIO 类型；Profile 决定实现装配。
  • 凭证上传（RM-1）、合同附件（CRM-R3）等文件类需求一律走 ObjectStorageService。
  • dev 磁盘实现需防路径穿越（禁止 key 含 ..），prod S3 需校验 bucket 白名单。

5.3 实时推送策略声明（RTP 模块前置约定）

  • 事件发布统一走 EventPublisher 抽象：dev=Spring 事件（进程内）；prod=Redis Pub/Sub（多实例广播）。业务侧无感切换（RTP-DV-02 落地）。
  • MVP 阶段前端以 3–5s 轮询兜底（RTP-DV-01），WebSocket 增量接入后轮询降级为断线兜底。

六、接口与 OpenAPI 约定

  • URL 前缀 /api；资源复数名词：/api/customers、/api/trade-orders、/api/remittances。
  • SpringDoc 扫描 /api/**；每个 Controller 用 @Tag 标注所属需求模块（如 CRM-C、OD），保证接口文档可与需求编号对照。
  • 接口版本策略：URL 不带版本号，破坏性变更走 /api/v2 新路径（当前 P0 单版本，规则先立）。
